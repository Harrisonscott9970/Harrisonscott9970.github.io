ScreenSense

A mobile wellbeing app that helps students manage screen time. It combines mood check-ins, journal entries and behavioural signals to give personalised suggestions, not generic advice.

The problem

Most wellbeing apps give the same advice to everyone: "take a break", "go outside".

That advice ignores how someone actually feels right now, how their mood has been trending, or what they've written about their day. I wanted to find out whether an app that adapts to the user's current state could give more relevant support than a simple rule-based approach.

Who it's for

Students and young adults who spend a lot of time on their devices and struggle with screen-time balance, digital fatigue or motivation.

How it works

  1. 1

    Mobile app

    React Native & Expo app in TypeScript: mood check-ins, journal, insights and suggestions.

  2. 2

    FastAPI backend

    API routes, Pydantic validation, database access and a service layer, documented with Swagger.

  3. 3

    Machine learning

    Three models analyse stress, mood trends and journal text.

  4. 4

    Recommendations

    An engine combines model outputs with rules to pick a personalised suggestion.

The machine learning

Stress classification

Random Forest

Uses behavioural and contextual features. I chose it because it handles mixed data well and is easier to interpret than deep learning.

~78% accuracy

Mood trend prediction

LSTM

Learns from a user's sequence of past moods, since how you felt earlier shapes how you'll feel next.

~0.08 validation MSE

Journal distress detection

BiLSTM + Attention

Reads journal text in both directions, with attention to focus on the words that matter most.

~85% accuracy

Prototype-level results on limited data. ScreenSense is a research prototype, not a medical device.

Engineering decisions

Clean, layered structure

I split the frontend (components, screens, hooks, services) and the backend (API, ML, models, services) into separate layers, so each part could be tested and changed on its own.

A control panel for the workflow

Running the app, backend and model training separately was slow and error-prone, so I built a one-click control panel to start everything and retrain models.

Testing

pytest covers API endpoints, input validation, model loading and recommendation output. The models were also checked with accuracy, F1 scores and confusion matrices.

Privacy by design

It collects only the data it needs, stores data locally where possible, frames suggestions as supportive rather than clinical, and follows GDPR principles.

Challenges & what I learned

Rebuilding after losing work

In February, part of the project was lost and had to be rebuilt. I re-prioritised and restored the core system first (backend, frontend, AI pipeline and recommendations), then used the remaining time on polish and testing. The project still earned a first.

What I'd do differently

  • Check backups more often and tag stable releases earlier
  • Plan smaller milestones and set aside more time for final QA
  • Test deployment and integration risks earlier
  • Run a larger real-world user study
